**M1.4 内核可靠性(0.5 周)**

## R2:采集与 CDP(2026-11 下 ~ 2027-01,8 周)

**目标**:平台从"种子数据演示"变为"真实数据驱动"——补齐数据入口与身份打通。

**M2.1 Web SDK 1.0(2.5 周)**
- TypeScript SDK(自动采集:pv/点击/停留;手动 API:track/identify/alias);
- 压缩后 <10KB、批量上报(5s/20 条)、失败重试、离线缓存;
- 采样率与开关由服务端下发;与 V15 的"SDK 编译器"合并:按项目配置裁剪特性编译。

**M2.2 Go 采集网关 Collector(2.5 周)**
- api-go 重构为单一职责 Collector:批量接收、Schema 校验、限流、写 Kafka;
- 独立 Dockerfile 与部署单元;/api-go 业务骨架(auth/gorm)移除;
- 降级路径:Kafka 不可用 → 本地缓冲磁盘队列。

**M2.3 数据管道与身份(3 周)**
- `events` 表按设计报告 T-2 重构(按日分区、排序键对齐);历史数据迁移脚本;
- Stream Consumer:事件落 CH + 维护 `id_mappings`(distinct_id ↔ user_id ↔ one_id);
- 用户画像宽表 `user_profiles` + 标签计算对接(标签引擎改读宽表);
- 分群 → 触达打通:分群结果可供订阅推送选择受众。

### 验收标准

```
✅ 接入 SDK 的演示站点,事件从发生到可分析 P95 延迟 < 60s
✅ 同一用户匿名→登录后,分析/分群中身份打通正确(one_id 唯一)
✅ Collector 压测:单实例 5k QPS 持续 30min 无丢失(Kafka offset 对账)
✅ SDK gzip < 10KB;主流浏览器(Chrome/Safari/Edge 近两年版本)兼容
✅ 全链路可观测:采集→Kafka→CH 各阶段延迟与积压有 Grafana 面板
```

## R3:智能化(2027-01 下 ~ 02 月,6 周)

**M3.1 LLM 网关(1.5 周)**:Provider 抽象(OpenAI/Anthropic/私有化模型)、租户 token 配额、结果缓存、超时与 mock 降级(复用 V7.2 资产)。

**M3.2 ChatBI(2.5 周)**:自然语言 → 查询 DSL(校验后进统一查询网关,**禁止裸 SQL**)→ 图表渲染;多轮澄清;对话历史与权限继承。

**M3.3 智能预警(1.5 周)**:现有 anomaly 骨架接统计检测(同环比/移动方差/STL),LLM 只做归因解释文案;告警收敛(同指标 30min 窗口去重)。

**M3.4 看板 AI 摘要(0.5 周)**:报表数据 → 摘要与异动提示。

### 验收标准

```
✅ ChatBI 对 20 个典型问句的 DSL 生成准确率 ≥ 80%,错误问题可澄清而非幻觉
✅ LLM 不可用时全功能降级,用户可见明确提示
✅ 单租户月 token 成本可配置、可查看、超限自动停用
✅ 智能预警在演示数据集上误报率 < 20%(人工标注对照)
```
