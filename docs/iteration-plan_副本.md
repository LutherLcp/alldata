## 风险管理

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| ClickHouse 查询性能不达标 | 分析功能受阻 | 提前建物化视图 + 采样查询兜底 |
| 前端包体积过大 | 首屏加载慢 | 严格代码分割 + 按需加载 |
| 数据量超预期 | 查询超时 | Redis 缓存 + 分页 + 超时降级 |
| 第三方服务不可用 | 推送/通知失败 | 队列重试 + 降级为站内信 |
| 多语言翻译滞后 | 国际化不完整 | 先中英双语，其他语言异步补充 |

## 质量保障

### 测试策略

| 层级 | 工具 | 覆盖率目标 | 执行频率 |
|------|------|-----------|---------|
| 单元测试 | Vitest | 80%（utils/hooks） | 每次提交 |
| 组件测试 | Testing Library | 60%（公共组件） | 每次提交 |
| API 测试 | Vitest + MSW | 90%（核心接口） | 每次提交 |
| 集成测试 | Vitest | 核心流程 | 每日 CI |
| E2E 测试 | Playwright | 核心用例 | 每周发布前 |

### 代码规范

| 规范 | 工具 |
|------|------|
| 代码格式 | Prettier |
| 代码质量 | ESLint（TypeScript + React） |
| 样式规范 | Stylelint |
| 提交规范 | Commitlint（feat/fix/docs/...） |
| 类型安全 | TypeScript strict 模式 |
| 参数验证 | Zod Schema（前后端共享） |

### CI/CD Pipeline

```
push/PR → Lint + TypeCheck → Unit Tests → Build → Integration Tests
                                              ↓
                                         Deploy Preview（PR）
                                              ↓
                                         Deploy Staging（main）
                                              ↓ (manual approve)
                                         Deploy Production
```
